# 旧版配置迁移

此功能从1.2起包含在Windows完整发布包中；其他系统使用下文的手动迁移方法。

## 首次打开

Windows新版第一次打开时，在主界面读取配置前显示一次“导入旧版配置”。需要继承旧设置的用户，同时打开旧助手，保存编辑并停止任务。向导每1.5秒自动检测来源，也可点击“重新检测”；只找到一个旧助手时自动识别，直接点击“导入并结束旧助手”即可。只有同时检测到多个旧助手时才显示列表，要求选定其中一个；检测刷新保留仍然有效的选择。

不需要迁移时点击“取消迁移”、按Esc或关闭窗口，新版正常启动。取消不会结束旧助手，也不会改写旧配置。提示只显示一次，后续启动不再要求打开旧程序；标记独立保存于安装根目录，不随导入旧配置而重置。

## 数据范围

| 旧版资料 | 导入内容 |
| --- | --- |
| `config/` | 全局偏好、全部实例、设备连接、任务勾选、任务选项、自定义关卡元数据等文件 |
| 根 `appsettings.json` | 实例列表、顺序、当前实例及原生定时设置 |
| 旧资源 `image/UserStages/` | 活动入口截图、关卡截图和附属页面标记，保留子目录及文件名 |

使用旧版 `interface.json` 解析资源位置，但不把它或旧运行代码、运行库覆盖到新版。仅旧安装目录内的绝对路径改为新版路径，外部模拟器与ADB安装路径保留。新版第一次加载资源时再执行既有选项迁移，新增选项使用其默认值。

## 完整性与失败处理

1. 从所选旧进程读取完整可执行文件路径，核对名称、启动时间和进程句柄；当前进程、同目录及相互包含的目录不能作为来源。
2. 暂存所有资料并核对复制内容和自定义截图引用。配置损坏、截图缺失或权限不足时显示原因，不开始替换新版数据。
3. 资料可读取后只结束该旧助手进程，重新读取最后落盘文件；不结束模拟器、游戏或其他助手。
4. 在新版 `backup/config-import-*` 中保留被替换的资料，再将配置和图片一起导入；失败时回滚已经替换的部分。旧目录及原文件始终保留。
5. 导入完成后才继续打开新版主界面。用户检查设备、任务选项和定时任务后使用；工具本身不运行游戏任务。

旧助手未保存到磁盘的修改无法保证继承。关闭旧助手使用精确进程终止，不依赖可能阻塞的退出确认。导入阶段暂时禁用取消，避免写入一半后继续启动；导入前可随时取消。系统断电、磁盘损坏或回滚也受权限影响时仍需手动从备份恢复。

## 手动迁移

已经取消、旧程序无法读取或使用其他系统时，关闭两边助手，先备份旧目录，再将旧 `config/`、根 `appsettings.json` 和 `resource/image/UserStages/` 复制到新版相同位置。若旧 `interface.json` 指向外部资源，以实际资源中的 `image/UserStages/` 为准。不要复制旧版整个资源目录覆盖新版流程。

## 实现入口

`tools/first_run/StartupHook.cs` 负责加载配置前的入口及一次性标记；`first_run.ps1` 负责向导和来源选择；`import_config.py` 负责资料暂存、进程身份检查、精确终止、备份与回滚。`tools/install_first_run.py` 接入发布包，`tools/run_dev.ps1` 构建启动程序集并为开发环境安装。
