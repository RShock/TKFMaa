# 商城购买（DailyShop）

入口：`DailyShopStart`。实现：`assets/resource/pipeline/daily_shop.json`、`agent/daily_shop.py`；选项：`assets/interface.json`。

入口经 [统一异常恢复](task_recovery.md) 执行 `DailyShopStartAttempt`；故障时先识别并尝试关闭广告或公告，每个任务合计最多两次，随后才按原设置重启或暂停。弹窗恢复跳回原后续识别，不初始化商城账目；游戏重启重做同样保留购买记录和累计扫描额度。

## 前置状态

游戏已登录，商城和协会商店可访问。分别确认各组商品复选框及折扣开关；本任务实际执行时会消耗游戏货币，未勾选商品不进入目标识别。

## 页面流转

1. 在主页识别商城并点击；若底栏商城选中图片已命中，则跳过入口点击。
2. 等待顶部“每日兑换”图片命中，再点击识别位置；随后识别交易所页签，不能按固定等待时间盲点。
3. 首次进入交易所时回顶一次，逐张完整卡片先检查SOLD OUT盖章图片，售罄则跳过，再按勾选商品图片识别。入口点击后立即记录本位置卡片，避免未打开详情时反复点击；待购信息继续保留。详情页不再做名称 OCR，识别到购买按钮图片后点击图片的精确中点。付款后先识别加载、货币不足和奖励；至少等待 2 秒后同一购买按钮仍在时才重试，同一候选合计最多 3 次点击，耗尽后交给原故障行为。
4. 购买并确认奖励后留在当前列表位置继续查找；没有可购买目标才向下滚动一次。每个商店累计最多向下滚动六次，最后一次滚动后的画面仍须扫描；购买成功不重置向下滚动总次数。
5. 交易所结束后切换协会商店，同样只在进入时回顶一次。全部取消时跳过该商店商品扫描，不执行第二轮全量复查。
6. 两个商店结束后点击城堡，经公共主页二次确认结束；货币不足时提前退出，未知页面不盲点。

## 商品分组与折扣开关

两家商店共五组，每组保留商品复选框，并另有默认开启的“仅购买打折商品”开关。开启要求商品与已知折扣标记位于同一卡片；关闭后允许已选商品按原价购买，不改变售罄排除、身份识别和购买次数限制。

| 商店 | 分组 | 商品 |
| --- | --- | --- |
| 交易所 | 常用道具 | 招募命令、紧急录用证、初级体力药水 |
| 交易所 | 材料 | 初级材料、中级材料 |
| 协会商店 | 属性石 | 烈风之石、光明之石、黑暗之石、火焰之石；洪水之石待补图 |
| 协会商店 | 调教道具 | 藤蔓、淫魔虫、电击棒、史莱姆、八目鳗 |
| 协会商店 | 其他 | 召唤契约、阿克色记录、银币 |

新配置默认选择招募命令、初级体力药水、召唤契约和阿克色记录，其余不选。旧配置按商品稳定ID拆分到各组，保留全部取消及重复商城任务各自的选择；内部ID中的“（打折）”保留用于兼容，显示标签去除此后缀。每组折扣开关默认开启，原先不限制折扣的契约、记录和常用道具也受本组新开关约束。

洪水之石展示为“待补图片，暂不购买”，节点禁用且不接入扫描；即使勾选也不购买，不引用虚构图片。未来补图时仍须保留商品身份、售罄和本组折扣条件。

### 图片依据

模板位于 `assets/resource/image/DailyShop/`，使用 MaaFramework 内置 TemplateMatch，不用商品名称或价格OCR。商品阈值0.96、交易所折扣阈值0.90、协会折扣阈值0.96均为匹配参数，不代表实测准确率。

- 招募命令沿用 `RecruitmentOrderTitle720.png`；初级体力药水使用 `BasicStaminaPotionIcon720.png` 替代旧标题模板。紧急录用证独立使用 `EmergencyEmploymentPermitIcon720.png`，新增常用道具复选框且默认不选，遵循本组仅购买打折开关。不能把旧节点名 `__DailyShopExchangeEmergencyRecruitmentTicket` 当成紧急录用证：它实际对应招募命令，现新增 `__DailyShopExchangeEmergencyEmploymentPermit` 区分两者。
- 药水与紧急录用证图标来自2026-11-11 MuMu设备内部1080×1920 ADB截图，经Maa原生统一720×1280后分别无损裁剪 `[295,404,99,102]`、`[112,403,99,106]`，不绑定数量或价格。现场药水×1、300交易所币、无折扣，紧急录用证×5、400交易所币、20%折扣；折扣额外裁剪 `[78,346,97,33]` 至 `EmergencyEmploymentPermitDiscount20_720.png` 并加入交易所同卡折扣模板列表。折扣开关默认开启时不购买现场这瓶原价药水；关闭该组限制后才允许购买已勾选原价商品。未执行匹配测试或购买。
- 交易所材料保留原120/240数字图片分类，另补充毒之粉、铁锭、史莱姆残液的初级图标，以及月光水、高级合剂的中级图标。图标独立于价格，支持这些已知材料原价购买；其他原价材料缺少身份图时不猜测购买。素材从已有ADB截图 `shop-exchange-top720.png` / `shop-exchange-bottom720.png` 无损裁剪，不新开任务或付款采集。
- 协会商品使用各自已有独立图标／标题模板。折扣开启时，两家商店均检查同卡20%、25%、40%、50%的已知图片，不再固定银币必须20%、其他商品必须50%；未识别的折扣仍跳过。
- 八目鳗使用 `LampreyIcon720.png`，默认不选，归入调教道具。图片来自2026-11-11设备 `127.0.0.1:16384` 的1080×1920内部ADB截图，经 Maa 原生缩放至720×1280后裁剪 `[472,406,108,80]`，避开爱心、数量、价格和折扣。采集现场为×5、50%折扣、25协会币，不把这些数量和价格绑定到商品身份；未执行匹配测试或购买。

商品卡片和购买按钮均点击本次识别框的精确中点 `[x,y]`。中心16×12购买框只用于局部稳定等待，不能传入矩形后让原生接口随机落点。

### 旧配置迁移

`tools/migrate_runtime_options.py` 在旧游戏选项迁移标记之前独立处理 `TkfmShopGroupsV1`，开发启动先备份实例JSON再写入；发布版扩展在空闲状态补做同样迁移，保留原任务列表到实例 `TkfmShopGroupsV1Backup`。根据每个旧商品名称拆分选择，不按变化后的索引猜测；清理任务层缓存的商品 `enabled`，防止已取消商品被重新启用。迁移幂等，不覆盖已迁移后的折扣开关。

## 预留商品素材

协会商店魔晶石已采集 `DailyShop/MagicCrystalIcon720.png` 与 `DailyShop/MagicCrystalTitle720.png`，仅预留用于后续图片匹配，尚未接入购买选项或自动购买流程。素材来自 2026-11-08 的设备内部截图，由 Maa 原生缩放统一至 720×1280 后裁剪；图标仅保留不受数量覆盖的上部特征，名称单独保存，不绑定数量、价格或折扣。当前现场为魔晶石 ×180、价格 100 协会币；素材尚未进行匹配测试。

## 识别与购买约束

- 所有坐标和模板按设备内部无损截图统一到 720×1280；`display_short_side: 720` 与 Maa 原生缩放保持一致，和电脑窗口尺寸、桌面 DPI 无关。新模板必须从 ADB 或 Maa 控制器截图裁剪。
- 先识别交易所或协会的货币图标作为卡片底部锚点，按实际纵坐标生成完整卡片 ROI。滚动惯性会改变行位置，不能一直使用固定上下两行坐标。相同锚点的多模板结果去重；超出列表可视区域的半张卡片跳过，锚点不明确时不购买。
- 本组折扣开关开启时，必须在同一卡片内同时命中商品/价格图片与顶部折扣百分比图片，不能借用相邻卡片的折扣。售罄、商品名称和详情均不执行 OCR。
- 材料按已采集图标或原120/240价格图片分类；本组仅限折扣时还须命中同卡折扣图片。关闭折扣限制不新增200/400等易与角色碎片重合的价格分类，未知原价材料跳过。
- 售罄不使用OCR，而是在每张完整卡片ROI先匹配 `SoldOut720.png` / `SoldOutAlternate720.png`。命中盖章直接跳过；检查未能启动时该卡不放行。售罄后底部价格、顶部折扣或部分商品图片仍可能命中，因此不能依赖商品识别自然排除。卡片中心16×16框只用于局部稳定等待，点击落在精确中点。
- 所有商品均以图片命中为购买依据；进入详情后只识别完整购买按钮图片，并点击其精确中点，不再核对详情名称。折扣限制开启时必须保留已命中的同卡折扣图片凭据；组配置缺失或非法时保持仅限折扣。
- 商品入口与购买按钮只在命中小区域局部稳定 300ms 后点击，稳定等待超时 1500ms；点击后通过下一轮状态识别推进，不以全屏静止判断动作完成。点击成功后由 `DailyShopRecordExchangePurchaseAttempt` / `DailyShopRecordGuildPurchaseAttempt` 记录尝试，额度按商品候选独立保存，不累计消耗其他商品的重试机会。只有奖励确认才标记购买成功；未知页面和次数耗尽仍失败，不盲目补点。
- 未勾选节点不执行目标识别。识别异常明确返回失败及原因，不使用异常回调的默认命中结果。
- 候选去重键包含商店、配置节点、滚动编号及槽位；入口点击成功后另按商店、编号、槽位立即记录已尝试卡片，不同分类不能反复打开同一卡。详情不符时关闭并跳过，不重置下滚总次数。手势成功不代表画面确实移动，底部滚动编号仍可能增加，因此每次扫描都独立排除售罄，不能仅靠编号去重判断可买。购买与奖励恢复返回当前屏，不回顶。
- 两个商店分别维护累计向下滚动计数；目标点击上限 24 次，每个商店累计向下滚动上限 6 次。第六次滚动后先扫描最后画面，处理当前屏可购买目标，再结束该商店。
- 商城入口及每日兑换图片均以识别结果驱动下一次点击，局部稳定300ms后操作；未知页面等待超时失败。货币不足、奖励及售罄图片各自独立判断。售罄素材来自2026-11-08暂停现场的设备内部1080×1920截图，统一至720×1280后裁剪 `[265,442,155,47]` 与 `[84,811,155,47]`；阈值0.85为匹配参数，当前模板尚未实机验证。

## 日志与结束条件

游戏设置“开发者选单”中的“开发者详细日志”默认关闭，连接初始化后可开启。它记录真实节点、算法、图片分数、识别框、实际点击坐标、后续识别、耗时与结果；完整事件保存在前端 `logs/detailed/` 的 JSONL。实现约束见 [前端日志扩展](../../../assets/resource/custom/doc.md)。

商品诊断保留卡片锚点分数、实际ROI、所属组及是否仅限折扣、商品/折扣及售罄图片分数与拒绝原因。售罄跳过为 `sold_out`，售罄检查未启动为 `sold_out_check_failed`，锚点不明确为 `card_anchors_unconfirmed`，异常为 `recognition_error`。普通日志直接提示检测到SOLD OUT、已跳过；日志不额外触发未勾选商品识别。

购买诊断包含完整按钮 `template_box`、局部稳定框 `click_box`、精确点击坐标 `click_point`、本次 `attempt` 及上限 `attempt_limit`；等待购买结果为 `waiting_for_purchase_result`，本候选额度耗尽为 `purchase_attempt_limit_reached`。日志中的点击成功只表示输入已发出，不能据此假定购买成功。

成功条件为两个商店完成有限扫描或因未勾选跳过，再确认主页；点击成功不能替代页面确认。实机覆盖范围和未覆盖分支写入本地记录，不把未完成的验证记为通过。
