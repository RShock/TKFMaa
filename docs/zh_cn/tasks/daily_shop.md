# 商城购买（DailyShop）

入口：`DailyShopStart`。实现：`assets/resource/pipeline/daily_shop.json`、`agent/daily_shop.py`；选项：`assets/interface.json`。

入口经 [统一异常恢复](task_recovery.md) 执行 `DailyShopStartAttempt`；故障时先识别并尝试关闭广告或公告，每个任务合计最多两次，随后才按原设置重启或暂停。弹窗恢复跳回原后续识别，不初始化商城账目；游戏重启重做同样保留购买记录和累计扫描额度。

## 前置状态

游戏已登录，商城和协会商店可访问。分别确认各组商品复选框及折扣开关；本任务实际执行时会消耗游戏货币，未勾选商品不进入目标识别。

## 页面流转

1. 在主页识别商城并点击；若底栏商城选中图片已命中，则跳过入口点击。
2. 先识别顶部“每日兑换”的选中态（文字与下划线实图），同时确认底栏商城选中；已选中则不再点击，直接识别交易所页签。未命中选中态才按原图片点击“每日兑换”，随后识别交易所页签，不能按固定等待时间盲点。从商城内开始任务同样支持已选中分支，不直接跳过交易所扫描。
3. 首次进入交易所时回顶一次，逐张完整卡片先检查SOLD OUT盖章图片，售罄则跳过，再按勾选商品图片识别。入口点击后立即记录本位置卡片，避免未打开详情时反复点击；待购信息继续保留。详情页不再做名称 OCR，识别到购买按钮图片后点击图片的精确中点。付款后先识别加载、货币不足和奖励；至少等待 2 秒后同一购买按钮仍在时才重试，同一候选合计最多 3 次点击，耗尽后交给原故障行为。
4. 购买并确认奖励后留在当前列表位置继续查找。付款后若已直接回列表，至少等待原两秒付款冷却，并确认商城高亮、同店完整卡片、无购买／奖励／货币不足弹窗，再清理待购信息继续扫描，不等待已经消失的奖励弹窗，也不消耗异常恢复额度。未捕获奖励不记作已确认购买，已尝试卡片仍去重。没有可购买目标才向下滚动一次。每个商店累计最多向下滚动六次，最后一次滚动后的画面仍须扫描；购买成功不重置向下滚动总次数。
5. 交易所结束后切换协会商店，同样只在进入时回顶一次。全部取消时跳过该商店商品扫描，不执行第二轮全量复查。
6. 两个商店结束后点击城堡，经公共主页二次确认结束；货币不足时提前退出，未知页面不盲点。

## 商品分组与折扣开关

两家商店共五组，组间以横线分隔。常用道具、材料、属性石、调教道具各保留默认开启的“只购买打折”开关；开启要求商品与已知折扣标记位于同一卡片，关闭后允许已选商品按原价购买，不改变售罄排除、身份识别和购买次数限制。“其他”不设组折扣开关，四个商品项独立控制。

| 商店 | 分组 | 商品 |
| --- | --- | --- |
| 交易所 | 常用道具 | 招募命令、紧急录用证、初级体力药水 |
| 交易所 | 材料 | 初级材料、中级材料 |
| 协会商店 | 属性石 | 烈风之石、光明之石、黑暗之石、火焰之石、洪水之石 |
| 协会商店 | 调教道具 | 藤蔓、淫魔虫、电击棒、史莱姆、八目鳗、蜡烛、匕首 |
| 协会商店 | 其他 | 召唤契约、阿克色、银币、银币打折 |

新配置默认选择招募命令、初级体力药水、召唤契约和匕首，其余不选，阿克色记录不再默认选中；已有明确选择保留，匕首按下文独立迁移补选一次。旧配置按商品稳定ID拆分到各组，保留重复商城任务各自的选择；内部ID中的“（打折）”保留用于兼容。其他组的召唤契约、阿克色、银币不限折扣，银币打折固定要求同卡折扣。银币两项均选时仍按同一卡片去重，不重复打开或购买。

洪水之石已补充实图并接入协会目标扫描，原占位case ID不变，勾选后启用。蜡烛新增到调教道具组；两者均默认不选，并保留商品身份、售罄和本组折扣条件。

### 旧配置迁移

`tools/migrate_runtime_options.py` 在旧游戏选项迁移标记之前独立处理 `TkfmShopGroupsV2`，已完成V1的配置也执行这次迁移，开发启动先备份实例JSON再写入；发布版扩展在空闲状态补做同样迁移，保留原任务列表到实例 `TkfmShopGroupsV2Backup`。根据稳定case ID保留选择，不按变化后的索引猜测；清理任务层缓存的商品 `enabled`、移除“其他”组旧折扣选项及 `DailyShopGuildOtherPolicy` 缓存，防止旧策略覆盖新商品语义。其余四组折扣设置及全部取消状态保留，迁移幂等。

新增匕首通过独立 `TkfmShopDaggerV1` 标记迁移：开发启动与发布扩展首次向每个商城任务的调教道具选择追加匕首，保存 `TkfmShopDaggerV1Backup`，清理该商品旧覆盖缓存；不重跑V2、不修改其他选择及折扣开关，之后用户取消不再强制补选。

## 识别与购买约束

- 所有坐标和模板按设备内部无损截图统一到 720×1280；`display_short_side: 720` 与 Maa 原生缩放保持一致，和电脑窗口尺寸、桌面 DPI 无关。新模板必须从 ADB 或 Maa 控制器截图裁剪。
- 先识别交易所或协会的货币图标作为卡片底部锚点，按实际纵坐标生成完整卡片 ROI。滚动惯性会改变行位置，不能一直使用固定上下两行坐标。相同锚点的多模板结果去重；超出列表可视区域的半张卡片跳过，锚点不明确时不购买。
- 本组折扣开关开启时，必须在同一卡片内同时命中商品/价格图片与顶部折扣百分比图片，不能借用相邻卡片的折扣。售罄、商品名称和详情均不执行 OCR。
- 材料按已采集图标或原120/240价格图片分类；本组仅限折扣时还须命中同卡折扣图片。关闭折扣限制不新增200/400等易与角色碎片重合的价格分类，未知原价材料跳过。
- 售罄不使用OCR，而是在每张完整卡片ROI先匹配 `SoldOut720.png` / `SoldOutAlternate720.png`。命中盖章直接跳过；检查未能启动时该卡不放行。售罄后底部价格、顶部折扣或部分商品图片仍可能命中，因此不能依赖商品识别自然排除。卡片中心16×16框只用于局部稳定等待，点击落在精确中点。
- 所有商品均以图片命中为购买依据；进入详情后只识别完整购买按钮图片，并点击其精确中点，不再核对详情名称。折扣限制开启时必须保留已命中的同卡折扣图片凭据；组配置缺失或非法时保持仅限折扣。
- 商品入口与购买按钮只在命中小区域局部稳定 300ms 后点击，稳定等待超时 1500ms；点击后通过下一轮状态识别推进，不以全屏静止判断动作完成。点击成功后由 `DailyShopRecordExchangePurchaseAttempt` / `DailyShopRecordGuildPurchaseAttempt` 记录尝试，额度按商品候选独立保存，不累计消耗其他商品的重试机会。只有奖励确认才标记购买成功；未知页面和次数耗尽仍失败，不盲目补点。
- 未勾选节点不执行目标识别。识别异常明确返回失败及原因，不使用异常回调的默认命中结果。
- 候选去重键包含商店、配置节点、滚动编号及槽位；入口点击成功后另按商店、编号、槽位立即记录已尝试卡片，不同分类不能反复打开同一卡。详情不符时关闭并跳过，不重置下滚总次数。手势成功不代表画面确实移动，底部滚动编号仍可能增加，因此每次扫描都独立排除售罄，不能仅靠编号去重判断可买。购买与奖励恢复返回当前屏，不回顶。
- 两个商店分别维护累计向下滚动计数；目标点击上限 24 次，每个商店累计向下滚动上限 6 次。第六次滚动后先扫描最后画面，处理当前屏可购买目标，再结束该商店。
- 商城入口及每日兑换图片均以识别结果驱动下一次点击，局部稳定300ms后操作；未知页面等待超时失败。货币不足、奖励及售罄图片各自独立判断。售罄素材来自2026-11-08暂停现场的设备内部1080×1920截图，统一至720×1280后裁剪 `[265,442,155,47]` 与 `[84,811,155,47]`；阈值0.85为匹配参数，当前模板尚未实机验证。

## 日志与结束条件

日志显示与滚动使用前端原生逻辑，界面定期裁剪到最近100条；删除自定义详细日志列表及开关。商城原有的商品决策、售罄与失败提示保留，识别细节继续从MaaFramework原生日志排查，不额外订阅事件重复生成JSONL。实现约束见 [前端日志约定](../../../assets/resource/custom/doc.md)。

商品诊断保留卡片锚点分数、实际ROI、所属组及是否仅限折扣、商品/折扣及售罄图片分数与拒绝原因。售罄跳过为 `sold_out`，售罄检查未启动为 `sold_out_check_failed`，锚点不明确为 `card_anchors_unconfirmed`，异常为 `recognition_error`。普通日志直接提示检测到SOLD OUT、已跳过；日志不额外触发未勾选商品识别。

购买诊断包含完整按钮 `template_box`、局部稳定框 `click_box`、精确点击坐标 `click_point`、本次 `attempt` 及上限 `attempt_limit`；等待购买结果为 `waiting_for_purchase_result`，本候选额度耗尽为 `purchase_attempt_limit_reached`。日志中的点击成功只表示输入已发出，不能据此假定购买成功。

成功条件为两个商店完成有限扫描或因未勾选跳过，再确认主页；点击成功不能替代页面确认。实机覆盖范围和未覆盖分支写入本地记录，不把未完成的验证记为通过。
