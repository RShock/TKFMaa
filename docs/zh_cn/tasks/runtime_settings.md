# 运行中修改配置

任务运行或暂停时可编辑普通／高级任务选项、游戏设置、自定义关卡及每日定时。保存仍使用原有配置位置，不弹额外确认；各设置按原有读取时点生效，不把保存动作当作重跑任务。

| 设置 | 生效时点 |
| --- | --- |
| 购买清单、扫荡／体力恢复开关、次数、活动页签及关卡选择 | 全部任务选项在启动队列时已经打包，修改后下次启动队列生效，当前队列尚未开始的普通任务也继续原选项 |
| 已保存自定义关卡的图片、名称及体力消耗 | 对应步骤开始时读取；尚未进入的步骤读取最新配置，当前已进入的步骤及恢复保留原值 |
| 遇到故障时重启／暂停、失败后继续策略 | 每个模块入口读取一次，修改影响后续尚未开始的模块；不会解除当前暂停或改变当前模块的重试决策 |
| 每日定时 | 保存后即时更新后续触发；当前队列不被打断，忙碌时仍按原定时规则跳过当次 |
| 已登记的单次派遣预约 | 保留登记时快照，修改普通任务选项不会改变已登记预约；需要改变预约时按原入口重新登记 |
| 其他原生游戏设置 | 按各功能原有读取时点使用保存值，不额外强制注入当前任务 |

任务选项区域及关卡编辑器显示生效说明。自动派遣开启时手动时间等由选项条件决定的禁用区域仍保留；任务列表的增删、排序与启停沿用原生保护。设备／资源切换、重新连接等会销毁控制器的操作仍遵循原生运行保护，不能在任务执行中切换当前设备或服务器。设备正在连接时暂不可编辑关卡，已关闭实例拒绝保存。

自定义关卡截图使用已有实时画面缓存，不另开截图控制器、不执行设备点击。新截图写入不可变新路径，删除配置不会删除可能被当前流程引用的图片；运行中编辑也不能覆盖正在使用的图片文件。

实现位于 `assets/resource/custom/TkfmRuntimeSettings.cs`、`TkfmCustomStage.cs`、`TkfmDeveloperSettings.cs`。编辑解锁只作用于设置输入控件，不改全局运行标记、不重新装配当前任务、不重置购买、体力或恢复额度；扩展释放时恢复原生绑定。故障恢复入口保持按模块读取设置，定时继续复用原生调度。
