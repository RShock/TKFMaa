# 统一截图

同一实例只保留一个设备控制器，任务识别与实时预览使用同一条设备内部截图链路。保留当前 MuMu `EmulatorExtras` 方式、所选 ADB 设备和 720×1280 识别基准。

## 连接与画面流转

1. `tools/run_dev.ps1` 正常关闭旧助手后，通过 `tools/migrate_runtime_options.py` 备份并为每份实例配置写入 `UseSeparateScreenshotTasker=false`，再启动前端。
2. MFAAvalonia 原生连接创建任务控制器；预览取得相同的控制器，取消另建截图 Tasker、资源与设备连接。预览和任务的请求由同一原生控制器处理，各自不持有独立 MuMu 连接。
3. `TkfmStartupLogFix` 在扩展构造阶段同步配置共享选项，空闲刷新为后续实例补充；执行或暂停中的原生任务不热切换。已有双连接通过正常退出并重启清理。
4. Pipeline 与 Agent 继续通过任务控制器取图，实时预览读取同一控制器缓存；自定义关卡采图仍读实时缓存，派遣倒计时仍读刚确认总览的识别帧。

## 约束与异常

- 不新增截图进程、控制器、截图算法或桌面抓图方式，不修改前端 EXE/DLL。前端内置独立截图实现通过原生选项停用。
- 截图失败时不能使用预览中的旧帧代替本次成功截图。自动启动先判断截图任务状态，再读取有效缓存；错误明确说明尚未开始当前任务，沿用所选故障暂停或恢复策略。
- 界面有图不等于刚提交的截图成功；保留截图失败诊断，不能把截图耗时统计的完成当作成功判断。
- 单实例只连接一台所选设备；多实例各有各的控制器，不把不同账号或设备的缓存混用。

## 实现与完成边界

配置迁移位于 `tools/migrate_runtime_options.py`，启动位于 `tools/run_dev.ps1`，运行时策略位于 `assets/resource/custom/TkfmStartupLogFix.cs`，自动启动状态检查位于 `assets/resource/custom/TkfmRunWithRecovery.cs`。截图异常处理恢复可用画面后继续按页面状态识别，不自动购买或启动游戏任务作验证。实际设备覆盖和未覆盖情况记录在本地实机记录。
