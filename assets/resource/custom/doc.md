# 前端资源扩展

## 加载与兼容

- 使用 MFAAvalonia 2.16.2 自带的 C# 自定义动作加载器，连接初始化时编译本目录顶层 `.cs`，无需修改 EXE 或另装匹配库。按钮在资源及连接初始化后出现。
- `TkfmDetailedLog` 与 `TkfmDeveloperSettings` 仅作为扩展入口注册，不加入任务流程，不执行设备动作。变更后重新启动开发版；重复加载须释放旧定时器及事件订阅。

## 更新源与更新渠道

- 本地魔改版本关闭版本自动检查、资源自动更新和前端自动更新，对应 `EnableCheckVersion`、`EnableAutoUpdateResource`、`EnableAutoUpdateMFA` 均为 false；更新页三个自动开关保持关闭并禁用。开发启动脚本须在启动前备份并写入全局配置，避免扩展加载晚于首次检查；扩展加载后保持该策略。手动更新操作保留，资源仓库及问题反馈元信息指向 `RShock/TKFMaaR`。
- 开发者设置随连接初始化把前端下载源固定为 GitHub，并清理 `DownloadSourceIndex` 与 `DownloadCDK`；更新页隐藏下载源下拉框、CDK、购买链接和到期提示，只保留 GitHub Token、代理及资源更新操作。不能只隐藏 Mirror 选项而不改已保存索引，否则仍可能从 Mirror 下载。
- 资源更新渠道仍是前端可见的 Alpha、Beta、Stable。三者不是不同分支，而是同一仓库 GitHub Release 的筛选条件：Stable 排除预发布，Beta 接受 beta 与 stable、排除 alpha，Alpha 接受全部；当前 UI 更新渠道控件由固定前端自身隐藏。
- MFAAvalonia 2.16.2 的发布工作流按 `v*` tag 创建同一仓库的 GitHub Release，tag 含 `-` 时标记为预发布。因此可用 `alpha`、`beta` tag 表示内测、公测，正式版用不带后缀的 tag；不能把“公测版/内测版”描述成独立代码分支。

## 启动阶段误报

- MFAAvalonia 2.16.2 的自动连接只用于加载资源，却会把空任务队列的 `onlyStart` 流程显示为“任务已全部完成”；`TkfmStartupLogFix` 在扩展加载时消费该次完成提示，用户下一次主动启动任务时由前端正常重置状态。
- `EmulatorExtras` 在刚连接时可能短暂拿不到首帧，不能立即当作截图链路故障。扩展在连接成功后提供 2.5 秒首帧宽限，期间不显示空画面警告；超过宽限仍无画面时保留原始警告。
- 修复依赖当前固定的 MFAAvalonia 2.16.2 私有状态字段 `_stopCompletionMessageHandled` 与 `_liveViewNoImageLogged`；升级前端时必须复核字段和启动流程，字段缺失时应静默停用修复，不能阻断连接。

## 统一截图

- 同一实例的任务识别、实时预览、自定义关卡采图与派遣倒计时共用一个原生控制器及其缓存；保留当前 MuMu `EmulatorExtras` 取图方式及 720×1280 基准，取消独立预览控制器，不新增 ADB 截图进程或桌面截图路线。
- 使用 MFAAvalonia 2.16.2 原生 `UseSeparateScreenshotTasker=false`：预览读图、提交截图及重置均由前端复用主控制器，独立截图 Tasker 不再创建。内置备用实现留在固定前端二进制中，不修改 EXE/DLL。
- 开发启动迁移在前端启动前逐实例备份并写入该设置；不能被旧 `TkfmGameOptionsV2` 标记跳过。`TkfmStartupLogFix` 构造时同步设置，空闲刷新补充新实例；运行或暂停中的原生任务不热切换控制器，已有双连接须重新启动清理。
- 任务截图返回状态必须先确认成功，再读取缓存并进行识别；截图失败明确提示尚未执行当前任务，不能以耗时统计完成当作拿图成功。自定义关卡继续只读实时画面缓存，派遣倒计时继续读取上一识别帧，均不增加独立连接。

## 自动启动与服务器

- 任务列表不提供“启动游戏”；“资源类型”直接选择工口服务器（内部ID官服，`com.pinkcore.tkfm`）或erolab服务器（`com.pinkcore.tkfm.erolabs`），共用资源目录。
- `TkfmRunWithRecovery` 在真实队列首次执行模块前用所选ADB路径、序列号查询pidof及前台Activity；未运行才启动并登录，后台进程只切回前台，查询失败不当作已运行。
- 游戏进程已存在时直接执行当前任务，不再运行 `GameLoginEnsureReady`，不先返回主页或等待广告；仅在后台时切回前台，不结束游戏。未运行或故障策略要求重启时才走登录分发，看到无已知遮挡的“出征”即完成，不要求广告出现或关闭。广告晚到、公告及左上返回均交给统一异常恢复；队列内完成进程准备后复用标识。
- 自动启动与定时派遣统一读取 `processor.Config.AdbDevice`，与前端创建控制器使用的路径、地址及 MuMu 元信息一致。实例配置中的 `AdbDevice` 在内存可能是 `AdbDeviceInfo`，不能用 `GetValue<JObject>` 读取，否则会退回空对象并误报配置缺失；不覆写设备配置或自动切换设备。
- 每次队列的新取消令牌触发新检测；只连接资源和只登记未来派遣不启动游戏。派遣关闭游戏后清除准备标识，后续模块重新准备。ADB查询10秒超时，响应停止，隐藏命令窗口。
- 空闲时迁移旧启动行的服务器索引、移除启动行，将征才旧开关子项次数提升到任务直接选项，数值不乘四；重复征才步骤各保留自己的次数。开发启动先备份并迁移实例JSON，发布环境由扩展补做迁移。

## 统一异常恢复

- 任务异常时依次识别公告、活动签到、完整左上返回按钮和广告箭头；识别到返回按钮就点击图片中心，再跳回原步骤按当前画面继续。完整按钮优先于仅含箭头的广告模板，不能把普通炼金页返回误报为广告关闭。公告关闭后需要继续登录时可使用返回或城堡回主页，看到出征即可，不要求广告出现。
- 普通返回与三类弹窗共享每任务两次额度，包含兼容登录路由的返回，重启前后保留；返回只负责导航，不清业务账目、不等于任务完成。
- 页面动作失败或后续识别超时后，先在当前控制器画面识别公告标题、活动签到页“结束时间”、完整返回按钮或广告箭头；已识别才操作。公告沿用关闭检查；签到页和普通返回直接点击识别框中心并由 `[JumpBack]` 返回原步骤继续判断，不把点击视为业务完成。没有已知目标时交回原异常出口，不猜测返回坐标。
- 每个任务合计最多两次恢复点击，广告、公告、活动签到与普通返回共用额度，包含兼容登录路由的返回及箭头兜底，游戏重启前后不重置。局部恢复不重新执行模块初始化、不清除业务命中次数、anchors、商城购买记录或资源额度；关闭失败仍执行原故障策略。公告继续登录路由，看到出征即可完成；活动签到页在正常登录分发器中也会处理，不等失败再关闭。
- 开发版启动与发布版空闲加载均迁移商城分组选项，按商品稳定名称保留勾选（含全部取消），新增折扣开关默认开启；旧商品清单和逐任务覆盖不应重新启用已移出的商品。
- `TkfmRunWithRecovery` 包装所有公开任务及保留的活动入口。原入口名保持稳定，原页面状态机移到同名 `Attempt` 主体；模块内部回跳必须指向主体，不能递归进入恢复入口。
- 弹窗关闭或返回后仍不能继续当前步骤时，再按故障行为消耗唯一游戏重启额度：结束所选渠道的游戏进程，重新启动并完成原登录确认，再从当前模块入口重做。登录任务自身重做已包含结束与启动，不叠加第二次重启。模拟器和助手保持运行。
- 同一步骤再次异常、恢复登录失败或恢复调度错误时不再重启；按下述故障行为处理，失败步骤仍记为失败。手动停止不触发恢复。连接、资源加载及扩展编译发生在模块外，不能由本动作恢复。
- 游戏设置新增“开发者选单”，按实例保存并包含“开发者详细日志”和“遇到故障时行为”。故障行为下拉框提供“重启/暂停”：重启默认开启并保留旧 `TkfmRestartFailedStep` 配置迁移，弹窗恢复仍失败后最多重启一次；暂停在弹窗恢复仍失败后冻结在节点边界并等待用户点击“继续任务”或停止。
- 原继续运行开关改名为“重试后仍异常时继续下一步骤”，关闭表示停止全部任务；缺少旧配置时默认关闭，已有明确值保留。行为下拉框执行中禁用，详细日志开关执行中仍可切换。
- 包名读取本实例“资源类型”的服务器选择；两渠道的冷启动与重启后登录均识别无已知遮挡的“出征”，不等待广告。恢复登录的 `GameMainReady` 必须自然结束子任务，不能使用会传播到父任务的 `StopTask`。
- 重试前清理页面导航命中计数，保留体力药、体力购买和调教次数额度及既有 anchors。征才以 `TkfmRecruitmentAttempt1..100` anchors逐次记账，保留待确认动作和领袖状态；批次完成节点及Gate不再作为总额度，恢复不能重新发放次数。
- 原生页面动作失败或识别超时先走弹窗恢复分支，模块返回失败后才执行原暂停／重启策略；正常体力不足等原有正常完成条件保持正常。异常出口必须明确失败，不能用成功的 `StopTask` 遮盖错误。日志注明首次失败、唯一重启、重试结果与最终停止或跳过策略。
- 入口可通过 `success_any_hit` 声明本轮必须命中的完成节点；包装器比较调用前后命中次数，Pipeline 以 `on_error` 安全返回主页但未命中完成节点时仍返回失败，避免静默跳过。
- 未注册到任务列表的旧 `AutoBattleStart` 依赖人工进入活动列表，重启后无法自动重建这一前置状态；重试必须继续识别列表，不能只因回到主页就报成功。实现与限制见 [统一异常恢复](../../../docs/zh_cn/tasks/task_recovery.md)。

## 暂停与继续任务

- 在普通及紧凑布局的原生开始/停止按钮左侧注入“暂停任务”按钮；任务运行时显示，暂停后文字变为“继续任务”。
- MaaFramework 5.x 没有原生 tasker 暂停 API。扩展在同步 `Node.*.Starting` 回调边界使用可恢复闸门冻结下一步识别、动作或等待，不调用 StopTask，因此保留当前任务队列和 Pipeline 命中状态。
- 继续任务只解除闸门并原地恢复；点击原生停止时，在停止按钮命令处理前释放闸门，避免暂停状态阻塞停止。任务结束、连接替换或扩展释放时同样自动放行。
- “遇到故障时行为=暂停”复用同一闸门，并在统一恢复动作内等待用户继续；解除后当前步骤仍返回失败，不伪装成成功，也不自动重启游戏。
- 暂停发生在事件边界而不是强制挂起线程；当前已开始的截图、识别或点击允许完成，下一次节点开始前不会再推进。实现不修改前端 EXE，也不重启游戏。
- 故障暂停保留失败页面供定位；例如购买点击已发出但详情仍在，应检查实际落点与后续状态机，不能仅因游戏画面未改变就认定 ADB 已断开。商城购买中心点击及有限重试由商城 Agent 和 Pipeline 处理，暂停服务不自动补点。

## 日志交互

- “开发者详细日志”开关位于游戏设置“开发者选单”，按实例保存，初始关闭，适用于该实例所有任务；日志卡标题栏不再保留旧“详细模式”按钮。开关只控制详细视图显示，连接后持续采集任务、识别、动作和节点通知。
- 普通及详细模式均复用日志卡的虚拟化列表，各自最多保留最近100条；详细模式混合显示普通及详细记录，关闭时仍只保留最近100条详细视图历史，重新开启不回放全部会话。完整详细记录持续写入磁盘，不重复回灌普通列表，重启前端不自动回放文件。
- 新日志批量更新后，鼠标不在日志卡内时自动滚动到最新一条底部；鼠标停留在日志卡内（含滚动条）时暂停自动跟随，移开立即恢复，不以是否接近底部决定跟随。浏览期间仍裁掉超出100条的最旧记录。
- 详细日志待显示队列同样最多保留100条；淘汰的历史行须释放订阅等资源。普通日志在集合变更通知完成后通过原生可释放集合裁剪，禁止在通知回调中修改源集合；每批更新合并滚动，文本换行及布局完成后仍跟随末尾。扩展重载恢复原内容并解绑新增事件。
- 展示任务 ID、真实节点名、识别算法、匹配分数、命中区域、实际点击坐标及结果。每次识别均记录，包含重复未命中；没有分数明确显示未提供，分数不代表实测准确率。
- 征才每次决策显示逐槽 OCR 原文与去除非中文字符后的词条、刷新原文和余量、动作额度、候选组合与角色、实际已选词条及拟选词条、计划时长、分支依据和当前等待原因；点击动作关联本次识别的选择依据。
- 明确区分领袖跳过、无保底且可刷新、刷新次数耗尽、刷新动作额度耗尽，以及按当前角色池组合判断的 9 小时 SR 以上保底征才。非保底兜底直接使用游戏默认的 1 小时且不选择词条，不宣称时长本身保证 SR。
- 商城扫描区分未勾选、未命中、售罄及详情名称不可读，并显示已选商品；完整事件保留槽位 OCR 或图片分数、模板与折扣复核，不为补充日志额外执行识别。
- 点击成功只表示动作完成，后续识别命中才记录页面确认。所有原生事件（包括开始通知）持续写入 `logs/detailed/` 每日、每实例 JSONL；界面显示识别、动作和任务结果，普通日志仍沿用原保存机制。
- 原生回调只复制事件入队，不能回调 Maa 查询或访问 UI；后台格式化并写盘，UI 线程批量更新历史、安装按钮，断开重连重新订阅。清空日志同步清空界面历史，并通过会话代数丢弃旧排队显示项，原 JSONL 文件保留；普通列表裁剪不能清空详细历史。
- 日志失败不阻止任务，须提示保存失败；重新加载扩展释放旧订阅、计时器和历史，并恢复原日志卡内容。

## 定时派遣

- 每日派遣支持立即执行和一次性预约。开启定时后，手动开始任务只登记预约并继续队列，到指定时间仅启动本实例的每日派遣，沿用登记时的地点和时长配置。
- 预约从当前控制器配置保存 ADB 路径与地址；缺少任一字段时拒绝登记。共享设备占用及到点设备变更判断读取同一配置，不能将类型转换失败当作设备变化；旧版已保存空设备信息的预约须重新登记，不自行猜测或修复快照。
- 时间使用电脑本地时区，支持 `HH:mm`（下一次该时刻）和 `yyyy-MM-dd HH:mm`（未来的明确日期）。重复登记替换尚未执行的预约；任务页日志标题栏可取消。执行前先持久化领取状态，失败或中断不自动重复执行。
- 助手须保持运行；扩展在首次连接/资源初始化后加载。重启助手后须先连接一次以恢复尚未执行的预约，过去的预约标记失效，不补跑。等待不占用任务队列，到点遇忙等待队列空闲。
- 定时运行先按当前实例“资源类型”所选服务器重新启动游戏，复用启动广告与主页识别，再运行既有派遣状态机。成功后可关闭游戏；失败或手动停止保留游戏现场。
- 可选管理 MuMu 12 指定实例：从所选 ADB 设备的 MuMu 元信息读取安装路径和实例编号，预约后关闭、到点启动、成功后关闭分别受复选框控制。不能使用全实例关闭、进程名批量终止或自动改绑其他 ADB 设备；配置缺失则拒绝登记该模式。
- 启停命令复用 MuMuManager 的 `control -v <index> launch/shutdown`。到点启动后有界等待原 ADB 设备启动完成，再交给前端连接；关闭只在本实例队列空闲且没有其他运行实例使用同一设备时进行。
- 派遣子任务的主页退出保留原识别条件，局部覆盖 `CommonStopOnMain` 为自然结束，以便外层执行成功后的关闭动作。
- 定时专用队列临时停用前端全局任务前后动作和失败后自动切换设备，并在结束后恢复；助手退出、电脑关机或休眠期间不会触发预约，不创建操作系统唤醒任务。

## 消耗体力内的自定义截图关卡

- “使用扫荡券”默认不勾选；标准关卡详情经 `DailyStaminaStageDetailModeDecision` 分流，普通战斗复用 `TkfmCustomStage` 的 `mode: direct` 子流程，识别开始、再次挑战及体力不足退出。直接战斗必须沿用显式用药、购买开关和额度，不受扫荡不足补刷开关限制；勾选时才启用扫荡入口、设置与开始节点。内置日常调教和仅有开始按钮的关卡继续原直接战斗路线。
- 自定义关卡属于“消耗体力”，不注册独立任务，不在日志标题栏、游戏设置中放入口。连接初始化、扩展加载后，扩展“体力消耗关卡”现有下拉框，显示内置关卡、本实例各份自定义关卡和“添加自定义关卡…”，同一选项下提供“管理自定义关卡”。
- 内置选项只保留“日常调教本”，过期活动和战争演习预设移除；自定义配置继续支持添加和删除。旧内置索引归到调教，带稳定配置ID的自定义选择归到自定义存储项，不按旧索引误选其他关卡。
- 消耗体力任务新增“活动页签”下拉框，默认“限时活动”，另一项“每日活动”。两项分别使用`Common/LimitedActivityTab720.png`和`Common/CurrentActivityTab720.png`模板识别未选中页签后点击，不使用OCR；旧任务没有该选项时按限时活动运行。
- 内置Cases仍由active.yaml生成，生成器仅在末尾追加固定存储项**TKFM_CUSTOM_STAGE**；本地命名配置不写回Interface或YAML。原生任务Option保存固定索引，并在“体力消耗关卡”Option.Data的custom_stage_profile_id保存稳定配置ID；任务级CustomStageConfig.attach.profile_id用于当前会话合并。界面把这个存储项展开成多份可读名称，重命名不影响关联。删除已引用配置显示缺失并拒绝执行，不退回其他关卡。
- 自定义动作只会在自定义Case被选中时运行；任务级profile_id为空时，回退到实例TkfmCustomStageProfilesV1.selected，兼容旧配置或前端未保存覆盖的情况。回退不改变内置关卡选择，因为内置Case不会进入该动作。
- 每实例保存多份配置，支持新增、重命名、复制和删除。“保存并使用此关卡”同时保存配置并选入打开编辑器的消耗体力步骤，其他步骤维持原选择。关闭放弃未保存修改；删除需二次点击确认。旧独立自定义任务在空闲加载时转换为消耗体力任务并保留原配置引用与资源开关。
- 活动入口和关卡截图必须复用`MaaProcessor.GetLiveViewCached()`返回的右侧实时画面缓存帧，不得另启动`adb.exe`或建立第二套截图链路。窗口每约1.2秒复制当前缓存；用户在游戏中切页，点击截取冻结后拖框并确认。实时画面未连接、缓存帧为空或图像无效时提示并等待主动刷新；不自动切换设备。运行任务或连接中禁止编辑，重载释放窗口、计时器与订阅。
- 9:16实时画面缓存归一到720×1280后无损裁剪，预览窗口大小不参与基准。选区不少于16×16且位于列表区域；关卡截图另保存顶部[50,60,600,80]作为页面标记。复用MaaFramework TemplateMatch，0.85为阈值，不代表实测准确率。
- 图片使用不可变随机目录保存在资源image/UserStages/；元数据仍使用实例TkfmCustomStageProfilesV1，保留旧数据。复制可共享不变图片，删除不物理清理图片，避免破坏引用。图片由Git忽略，备份同时保留实例配置和图片目录。
- 配置不完整、图片损坏或缺失、非法体力消耗、路径越界在动作前失败，不重启游戏。前半段使用无状态路由：以节点rate_limit=1000低频、同时检查主页“出征”、所选活动页签、活动入口图片和关卡图片，命中哪个就点击哪个并回到路由。默认限时活动，可切换每日活动；任一页面开始任务均可继续，直到关卡详情被确认。
- 关卡列表必须先命中顶部页面标记才点击目标或下滚；每次先找图，最多下滚6次，路由最多30次命中/30秒，耗尽明确失败，禁止无间隔快速扫描。
- 进入军团扫荡详情复用既有扫荡与补刷；仅有开始按钮时直接战斗，复用再次挑战及体力不足退出。体力消耗继续按配置比较，用药及购买沿用消耗体力现有显式开关和额度。导航或战斗异常沿用一次重启恢复。
- 两张用户截图不覆盖额外分类、横向分页、二维地图和自动编队。顶部变化、截图包含动画或倒计时需重新录制。未主动要求测试时不运行测试，不把生成配置或界面启动当作实机验证。

## 派遣倒计时续约

- `DailyDispatchStart` 的 `custom_action_param` 必须显式传 `{}`。Maa 对缺省参数传出 JSON `null`，`TkfmDispatchSchedule` 必须把参数解析及全部执行逻辑放在异常保护内；任何异常只能返回失败，不得逃逸到 native callback 并终止 MFAAvalonia。
- “自动计算下次派遣时间”默认关闭；三队派遣中及取消按钮均确认后、返回主页前，从同一张设备内部截图逐栏 OCR 读取完整 `hh:mm:ss`。三个值都有效才按最长值加5秒生成下一次预约；不使用地点的理论时长代替实际剩余时间。
- OCR 为动态时间读取，三个独立 ROI 基于既有设备截图的720×1280基准。读取失败只记录原因，正常完成当前派遣，不生成猜测预约。原有完成/闲置处理优先，重新派出后仍读取新的三队倒计时。
- 当前流程及关闭游戏动作成功后才保存预约，保存地点/时长和调度选项快照；预约执行完成、恢复原队列设置后再续约，避免旧预约收尾覆盖新预约。失败或停止不续约。
- 每实例最多一份派遣预约，新预约替换尚未执行的旧预约；日志标题栏可取消。取消或离线错过后不自行重建，取消勾选不删除已登记预约，须另点取消。开启自动计算时忽略手动预约时间，直接进入派遣读取倒计时并续约。

- 显示名称使用“自动计算下次派遣时间”，保留旧选项ID以兼容已有勾选。通过原生选项绑定禁用并灰显手动时间区域，不覆盖原时间；取消自动计算立即恢复编辑，任务运行时仍遵循前端原有禁止编辑规则。
- “派遣成功后关闭游戏”归入“定时派遣”子选项，关闭定时派遣时不关闭游戏；空闲时迁移旧顶层选项到子选项并保留选择。
- “定时启停MuMu模拟器”右侧使用原生问号提示，悬停文字为“当用户安装mumu模拟器时，可自动开关模拟器实现省电”。

## 配置每日定时

- MFAAvalonia 2.16.2 原生 `TimerModel` 已有整体任务定时执行能力；`TkfmDailySchedule` 只扩展 UI，复用原生计时、去重和持久化，不建立第二套每日轮询调度器。
- 资源扩展加载后，在普通及紧凑布局“开始任务”右侧显示“定时任务”。窗口绑定打开时的实例稳定ID；可启停每天执行，并填写多个 `HH:mm` 时间，保存后生效，关闭窗口放弃修改。
- 每个时间点对应一条原生每日启动定时器，运行该配置触发时勾选的任务及选项；编辑仅管理该实例的每日启动项，保留其他实例、按周、按月及停止任务定时器。
- 启用时打开原生“选用配置”，关闭“全局启动全部配置”和“强制定时启动”，这些全局设置影响在窗口中明确说明；不覆盖其他定时器已选择的目标。配置正在运行时原生逻辑跳过当次，不中断现有任务，不排队补跑。
- 使用电脑本地时间；助手关闭、关机或休眠时不触发，错过不补跑，不创建系统唤醒任务。保存不会立即执行任务。按钮首次出现仍依赖资源扩展加载，保存的原生定时器由前端在后续启动时恢复。
- 重复加载释放旧UI定时器、按钮和编辑窗口；新增源码仍通过原生动态加载器装载，不修改前端EXE。
