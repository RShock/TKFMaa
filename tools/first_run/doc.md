# 首次启动配置迁移

- Windows 的 .NET StartupHook 在 MFA 读取用户配置前打开一次迁移向导；保留原有 libloader，不修改 EXE/DLL。安装目录独立标记记录已展示，取消、关闭和成功后均不再自动提示；开发启动不清除此标记。
- 用户先打开旧助手，向导每1.5秒按进程完整路径和安装目录中的 TKFMaa/TKFMaaR 元信息自动检测。唯一来源直接识别，不显示选择列表；多个来源才要求选择，刷新保留仍然有效的选择。始终由用户点击导入后才结束旧助手。排除当前程序及重叠目录；启动时间、进程句柄和完整路径共同限定待结束进程。
- 导入整个 config、根 appsettings.json 和旧 interface 指向资源中的 image/UserStages。保留截图相对路径，检查配置引用及截图文件，不复制旧版代码、interface 或运行库。旧目录内的绝对路径调整到新目录，外部模拟器路径保持原值。
- 先暂存并检查完整资料，再结束用户选定的旧助手，重新读取落盘数据，备份新版数据后导入。失败回滚已替换文件，旧目录始终保留；取消不结束进程、不导入数据。无法读取进程或截图缺失时提示失败并允许刷新或取消。
- 启动模块使用前端自带 .NET；向导优先 PowerShell 7、回退 Windows PowerShell，导入器使用发布包 Python 及一并打包的 json-with-comments，不能依赖维护者的虚拟环境。构建在 Windows 矩阵安装 net8.0 启动程序集和部署配置；其他平台沿用手动复制流程。
- 必须先备份 config、appsettings.json 和用户截图再升级，不能将向导等同于停电／磁盘损坏保护；未保存到磁盘的旧版编辑无法保证继承。新建配置及迁移的定时设置需由用户复核，不由迁移工具启动游戏。
- 向导随启动它的前端退出而关闭；导入器持有单独文件锁，后续启动在读配置前等待导入结束。开发强制重启遇到正在导入时停止重启，空闲向导按本目录脚本参数及前端父进程精确结束；若向导已随父进程退出则跳过，不能把退出中的空路径误报为进程身份改变。
